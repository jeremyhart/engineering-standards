The required level is max(impact, ambition) — impact sets the floor and can only raise the bar. This project rates 3 on disruption (the warehouse stops when it’s down) and loss (mid-fulfillment state has no second copy).

Level and maturity are not the same thing

The level is the bar the project owes, set by consequence — its names (Personal, Shared, Critical, Contracted) describe what is at stake, never how good the project is. Maturity is how far the project currently reaches against that bar; a level-3 project can sit at any maturity, and being far short of the bar never makes it a “level-1 project”. The coverage bar alongside is the maturity picture; closing it is this report.

01 · Priority

Why these come first

Not a list of the worst rows — the table below has all 70. This is the one shared risk they combine into, and the order that unblocks the rest.

The risk

Nothing stands between a bad change and production. main deploys straight to the warehouse floor with no review gate, no CI, no tests — and a live copy of production configuration sits in git history.

Why together

These four are one failure mode, not four: branch protection is worthless without a required check, a required check needs a workflow to run, and the committed .env means any of the two collaborators’ compromised accounts is a production credential leak. Fixed in sequence, each makes the next enforceable.

The order
  1. 1 CI workflow
  2. 2 Branch protection requiring it
  3. 3 Secret scanning + Dependabot
  4. 4 Remove the committed .env
The cost

About two days together. Everything else in this report ranks behind these four because none of it is enforceable until a gate exists.

07 · The case for improvement

Three to four weeks, alongside feature work

This is the system of record for order fulfillment — pick, pack, bin location, ship status. It has no review gate, no tests, and no managed config store.

The fix is roughly three to four weeks of configuration and process work, done alongside feature work — not a rewrite. Deferring it means every new feature inherits the same gaps and has to be revisited later.

Highest-leverage first actions, ranked by what unblocks the rest:

  1. Branch protection on main — require PR + status checks, apply to admins (currently absent).
  2. One GitHub Actions workflow running lint, tsc --noEmit and a test command on every PR, marked required — this alone moves Linting, Type safety, PR checks and Unit testing off zero.
  3. Enable Dependabot alerts and GitHub secret scanning (repo Settings → Security, both confirmed off).
  4. Delete the committed .env, add .env.example, and confirm no real secret survives in history.
  5. A minimal Vitest suite over the fulfillment-atomicity and bin-assignment logic in pickBinAssignment.ts and netsuite-post — the highest-consequence, currently untested code path.

Retrofitting cost grows with the codebase: every edge function shipped without the shared requireUser/requireAdmin pattern, and every migration shipped without expand-contract discipline, is harder to fix once dependents exist.
